# Camada de método UX nos cases (proposta)

Data: 2026-08-28. Status: proposta, aguardando escolha da Pietra.

## Problema
Os cases contam decisões mas mostram pouco método. Nenhum projeto teve entrevista com usuário, exceto Straatos (contato direto com o cliente, que é o usuário). Qualquer artefato precisa dizer de onde veio.

## Proposta
Artefatos curtos (frase de até 12 palavras + imagem descritiva) inseridos entre os blocos de texto, cada um com etiqueta de evidência:
Client sessions (só Straatos) · Domain expert · From the spec · Designer judgment.

Por case:
- Kota: stakeholder map, assumption mapping (question loop), service blueprint (duas cópias), heuristic evaluation do processo em papel, object model (OOUX) da grammar, state inventory.
- Straatos: affinity map das sessões, journey map campo → relatório, JTBD por papel, design principles, walkthrough com o cliente (se aconteceu).
- Wazi: ecosystem map (soberania como fronteira), concept model form → graph, scoring model, role cards derivados da spec (não personas).
- Supply chain: process comparison (estático vs vivo), triangulation model, card sort de sinais por framework, heuristic evaluation do tooling antigo.

## Regras de linguagem
"the client told us" só no Straatos; "confirmed with the domain expert"; "role derived from the spec" em vez de persona; "walkthrough" ou "heuristic review" em vez de usability test; "the regulation requires" em vez de "research showed". Sem travessão.

## Produção
Straatos primeiro (única evidência de cliente), depois Kota. Diagramas em SVG/HTML light, Inter, mesma grade nos quatro. Inputs necessários da Pietra: bullets do que o cliente disse (Straatos), perguntas reais do question loop e uma matriz de estados (Kota).

Artefato publicado: ver link no handoff do dia.
